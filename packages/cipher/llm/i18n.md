# Cipher — i18n & RTL Guide

## Recommended locales

| Locale | Status | Notes |
|---|---|---|
| `en` | First-class | Native target |
| `de`, `fr`, `es` | First-class | Inter has full Latin coverage |
| `ja`, `zh` | Tested | CJK handled via Noto fallbacks |
| `ru` | Tested | Inter has Cyrillic |
| `ar` | Tested | Code blocks remain LTR |

## Font fallback stacks

```
CJK:        'Noto Sans JP', 'Hiragino Sans', sans-serif
Arabic:     'Noto Sans Arabic', sans-serif
Cyrillic:   'Inter', system-ui, sans-serif
```

## RTL stance

**Supported with carve-outs.**

What flips:
- Layout (logical CSS)
- Directional icons

What stays LTR regardless of document direction:
- Code blocks, terminals, command output
- Diff views
- File paths, version numbers, hashes
- Stack traces

This is critical: code is left-to-right by definition, even on Arabic-language pages.

## Layout gotchas

- **Tabular numerals.** Always enable `font-feature-settings: "tnum";` for numeric columns
- **Long localized error messages** can break tight tables; allow word-wrap on error rows
- **Date/time formatting** uses ISO-8601 in technical contexts; locale-formatted in user-facing copy

## For LLMs

1. Wrap any code/terminal block with `dir="ltr"` regardless of page direction
2. Use `font-variant-numeric: tabular-nums` on numeric data
3. Use ISO-8601 timestamps (`2026-05-08T14:32:09Z`) in technical UIs
4. JetBrains Mono only covers Latin + Cyrillic — code in CJK falls back to system mono
